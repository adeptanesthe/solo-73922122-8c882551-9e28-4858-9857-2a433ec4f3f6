# 唤醒词缺报核对（wakeup-audit）

设备唤醒日志缺失一段时，用同期留存的模型分数重建缺报区间内的触发帧。

## 规则

- 帧号从 0 起；缺报区间包含首尾；分数为整数，最多 200000 帧。
- 未处于冷却的帧，分数达到阈值即触发；触发后接下来 `cooldown`（0～2000）帧冷却。
- 录制开始时可能仍在冷却，剩余帧数 `r ∈ [0, cooldown]`，每种 r 是一种"解释"。
- 缺报期间照常触发和冷却；**缺报区间外**有触发的帧必须**恰好**是回执列出的帧
  （区间外多出的触发、回执帧未触发都会否决该解释；区间内回执帧同样必须真实触发）。
- 缺报区间内：
  - **补记**：所有一致解释都触发的帧（含区间内已回执的帧，状态标 `received`）。
  - **待核**：只有部分一致解释触发的帧。
  - 无任何一致解释 → **冲突**，补记列表留空，并列出每种 r 的否决原因。

## 算法（不为每种初始冷却逐帧重扫分数）

1. 一次 O(N) 倒序扫描构造 `next_cross[i]`：从帧 i 起第一个达阈帧。
2. 把"下一可触发帧 s"沿函数链 `s → next_cross[s] → s + cooldown + 1 → …` 记忆化，
   所有 r 的链共享后缀；全部链总长度 O(N + cooldown)，20 万帧实测约 0.2～0.3 秒。
3. 对每种解释只做链上序列与回执的集合核对，再求区间内触发集的交集/并集差。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

页面支持粘贴或从 `.txt/.csv` 文件导入分数（空白/逗号/换行分隔），
重新核对会自动撤下旧结论与旧补记下载（旧链接再访问返回 HTTP 410）。

## 过滤试跑（背景声模板拦截）

设备反复把同一类背景声认成唤醒词时，在页面下方"过滤试跑"面板里用模板过滤试跑，
**不会改动上面的缺报核对**。

### 输入

- 复用同一套模型整数分数（最多 200000 帧）、阈值、冷却帧数；
- 容差：非负整数，即 8 帧窗口"逐项绝对差之和"（L1 距离）的上限；
- 至少一个要保住的真口令帧。

### 规则

- 从**可触发状态**（初始冷却剩余 r=0）按原规则回放：未冷却且达阈即触发，触发后冷却 `cooldown` 帧。
  若原规则本身就漏掉真口令帧，不允许开始试跑。
- 工程师只能从**未标注的当前触发帧**里挑模板帧，且帧号必须 ≥ 7（有完整前 7 帧）；
  取当前帧与前 7 帧共 8 个分数作为一条模板，最多累计 8 条，同一帧不能重复作模板。
- 每加入一条模板都**从原分数重新回放**。达阈且未冷却的帧：
  - 帧号 < 7（凑不齐 8 帧）或当前没有模板：按原规则触发；
  - 否则按模板加入顺序逐条算 L1 距离，第一条距离 ≤ 容差的模板命中即**拦下该帧，
    且不启动冷却**，不再与后续模板比较；全部不命中才按原规则触发并启动冷却。
- 单遍线性回放，每帧只处理一次：已比过的帧、已生效的模板都不会重算距离
  （响应里的 `stats.distance_evaluations` 可核对实际距离条数）。
- 任一真口令帧不在触发帧里即判定**不通过**：该模板被拒绝，**保留原有模板和原有结果**，
  并列出漏掉的真口令帧；只有通过才真正更新模板。
- 页面始终展示触发帧（含真口令标注）和拦截帧（含命中模板序号、L1 距离与 8 帧窗口）。
- 改动分数、阈值、冷却、容差或真口令帧任一输入即结束当前试跑；在途请求的迟到结果
  自动作废（前端按请求世代丢弃，服务端会话也只保留最近 16 个，旧会话返回 410）。

### 接口

- `POST /api/trial/start`：开始试跑，返回基线回放（无模板）与候选帧。
- `POST /api/trial/{session_id}/template`：加入一条模板并重放；
  不通过时 `accepted=false`，附 `candidate_missed_protected`，原模板与原结果保留。
- `GET /api/trial/{session_id}`：查询当前试跑状态；会话失效返回 410。

## 接口

- `POST /api/check`：提交核对，返回结论、补记、待核或冲突否决原因。
- `GET /api/results/{id}/backfill.csv`：下载最近一次核对的补记 CSV
  （UTF-8 BOM，列：frame, score, status；冲突态 409，失效链接 410）。
- `GET /api/health`、`GET /api/limits`（含 `max_templates=8`、`template_window=8`）。
